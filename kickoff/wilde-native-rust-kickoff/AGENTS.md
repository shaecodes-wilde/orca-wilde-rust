# Wilde Native kickoff rules

Inspect the actual checkout and applicable repository instructions first. Do not replace root `AGENTS.md`.

Target native Rust UI/runtime; do not silently substitute a web-rendered shell. Keep the working app and production profiles untouched. Use synthetic data, separate dev identity, endpoints and credentials. Preserve existing cross-platform/remote contracts.

A1 leads five scoped workers: two Astra roles and four Opus roles total. Verify real model routing. One owner per path; contracts precede cross-owner changes. Use isolated worktrees and direct messages; preserve decisions, tests and commit references in GitHub, or mark local records pending publication.

Prefer three implementation workers and one heavy build per host. Start small, measure, then expand. Never bypass permissions or launch foreground test windows on Shae's desktop.

A migration needs behavior, failure/recovery, cleanup and comparable performance evidence. A stub or mock is not parity. Record untested platforms explicitly. No production cutover, force push, secret export or destructive cleanup.

Explain meaningful changes and tradeoffs in plain English. Teach at decision points, not every command.

After verified integration and durable evidence, close task-owned processes and remove only clean, registered worktrees. Preserve ignored/unique files. No force removal, broad cleaning or age-based deletion. Unknown cleanup state means retain and report.
